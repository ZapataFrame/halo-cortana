# H-11 — Conversación PC y cancelación verificadas

Fecha: 2026-10-10. Responsable: Codex. Rama: `codex/reconocimiento-voz-pc`, base del incremento `d119c50`. Objetivo: completar la validación UI de conversación independiente de la aceptación humana H-16.

## Cambios y motivo

El prompt compartido todavía indicaba «no tienes voz». Una pregunta real desde el control obtuvo: «No, soy una demo holográfica y no tengo capacidad de voz ni herramientas para ejecutar lecturas en voz alta», aunque TTS y su botón ya existen. Se corrigió `server/providers.js` para reconocer avatar, lectura TTS local y dictado revisado, manteniendo límites: no herramientas, acciones de simulador/dispositivos ni afirmaciones de captura/reproducción actual. No cambia proveedores, claves ni modelos.

`tools/serve-chat-qa.mjs` y `npm run qa:chat -- normal|delay` permiten repetir el ensayo con el backend de producto y LLM real en loopback 3002. La conversación queda separada de 3000. El modo delay retiene solo respuestas reales de mensajes con `[QA_CANCELACION]`, después de recibirlas de Gemma, hasta Enter en la terminal o 20 s. La retención ignora intencionalmente la cancelación para comprobar que `createApp` descarta la entrega antigua. No inventa respuestas ni altera el cliente. Guion en `docs/PRUEBAS_CHAT_PC.md`.

## Verificación ejecutada

Entorno: PC Linux, Node 22.22.2, navegador integrado Codex; proveedor real Ollama Cloud/Gemma 4 31B, clave existente solo en backend. Sin micrófono ni reproducción TTS en este ensayo. Plan/cuota de la cuenta no inspeccionados y no se activaron pagos.

| Verificación | Resultado |
|---|---|
| Respuesta antes/después del prompt | Negaba voz antes; después respondió «Sí, la aplicación puede leer mis respuestas utilizando la voz local de tu PC». Generación real desde UI, no inferencia a partir del prompt. |
| Tres preguntas distintas + seguimiento | Reconoció TTS, recordó ORION-27, negó crear un tanque y recuperó ORION-27 en la cuarta pregunta. Tiempos mostrados 0.6/0.7/0.5/0.4 s; valores redondeados de UI, no benchmark preciso. |
| Avatar durante recorrido | Superficie ready, Cortana y cuatro materiales texturados en los cuatro puntos de control. Preview del PC conservado; visor separado inspeccionado tras el ensayo. No validación móvil/óptica ni benchmark FPS. |
| Cancelación natural, primer intento | Gemma respondió en 0.9 s antes de que el clic Cancelar pudiera ejecutarse; el botón desapareció y se agotó su espera. La solicitud completada no cuenta como cancelada. |
| Cancelación con entrega real retenida | Terminal confirmó generación real retenida; Cancelar mostró estado cancelado y desbloqueó el editor. Un mensaje nuevo respondió ORION-27 en 0.7 s, conservando el contexto anterior. |
| Entrega antigua y recuperación | Tras vencer la retención no se incorporó respuesta NOVA-13 ni se sobrescribió la nueva respuesta. El ensayo conservó dos respuestas de Cortana para tres mensajes, con el mensaje cancelado visible sin respuesta. |
| `npm test` | 74/74 correctas. Contratos, proveedores, concurrencia, cancelación/retornos tardíos, voz y dictado. Fixtures complementan las respuestas/UI reales; no las sustituyen. |
| `npm run build` / diff | Compilación correcta; JS 666.51 kB/171.32 kB gzip y advertencia >500 kB conservada. `git diff --check` correcto. |

La restricción histórica de `locator.fill` no se reprodujo en este entorno. Entrada y Enviar funcionaron mediante las APIs documentadas del navegador. Un intento tras abrir el visor apuntó a la misma pestaña reutilizada y agotó la espera del campo: se inspeccionó la URL/DOM y se volvió al control, sin mecanismos alternativos. El entorno ofrece una vista; no se atribuye una validación simultánea PC/móvil a navegar entre rutas.

El proceso de QA se inició sin stdin interactivo; Enter por la herramienta no pudo enviarse. Se usó la liberación automática de 20 s y se comprobó después la conversación. No se presenta ese intento como una liberación manual exitosa. Las instrucciones interactivas y alternativa por vencimiento quedan en la guía.

## Evidencia y límites

`docs/reports/evidence/H-11-chat-ui.json` conserva mensajes ficticios, respuestas reales, comprobaciones de avatar, cancelación y verificación tardía. Las capturas de control/visor corresponden a PC. El servidor principal permaneció en revisión 0/idle mientras se ensayó en 3002.

Al cerrar se detuvo el servidor de ensayo y se reinició el proceso principal, después de confirmar que seguía en reposo, para aplicar el prompt corregido. El control del puerto 3000 volvió a mostrar Cortana ready, cuatro materiales texturados, conexión activa, TTS Daniela y reconocimiento local preparados. El primer intento de reconexión al navegador agotó la espera; una conexión nueva permitió comprobar el control, sin repetir las llamadas LLM ni abrir el micrófono.

H-11 queda DONE tras verificar esos criterios. H-16 pasa a BLOCKED por Q-12: falta participación con micrófono/permisos/frases humanas ≥8/10, no implementación. H-17 espera esa aceptación. H-12 sigue esperando H-07 móvil, H-13/H-14 el montaje físico y H-20 una clave GPT válida. No se reactiva el simulador ni se declara voz/óptica certificadas por este ensayo de texto.
